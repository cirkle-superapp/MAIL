# NEXT-GENERATION SEARCH ENGINE

## Master Product Blueprint + Implementation Specification

### Version 1.0

---

# 1. PRODUCT VISION

Build a global, independent, Google-class search engine that provides:

* Its own web crawler
* Its own web index
* Its own ranking engine
* Semantic and lexical search
* Entity and knowledge-graph search
* News search
* Image search
* Video search
* Document search
* Local search
* Community search
* Academic search
* Official-source search
* AI-assisted search
* Deep Research
* Search transparency
* User-controlled personalization
* Privacy-first search
* Explicit advertising separation
* Search-quality and source-quality signals

The product must **not be a Google clone**.

Its objective is to preserve the power of large-scale web search while correcting common search-experience problems:

> Too much SEO manipulation, repetitive results, insufficient source transparency, excessive personalization, unclear advertising, overreliance on AI summaries, poor control over search behavior, and difficulty distinguishing primary, official, community, commercial and secondary information.

The core philosophy is:

> **Search should help users discover the web, understand the information, evaluate the evidence, and control how the engine searches.**

---

# 2. NON-NEGOTIABLE PRODUCT PRINCIPLES

The system must follow these principles throughout the architecture.

## 2.1 Relevance over SEO

Ranking must prioritize usefulness and relevance rather than pages optimized primarily for search-engine visibility.

## 2.2 Evidence over AI confidence

AI must never treat confidence as proof.

AI-generated claims must be tied to retrieved evidence whenever factual claims are made.

## 2.3 User control over hidden personalization

Users must be able to understand and control personalization.

## 2.4 Diversity over repetition

Ten copies of substantially identical content should not consume ten major result positions.

## 2.5 Freshness without sacrificing quality

Newer content should not automatically outrank better content.

## 2.6 Clear information categories

The engine must distinguish:

* Organic
* Sponsored
* Official
* Government
* Academic
* News
* Community
* Commercial
* Primary source
* Secondary source

## 2.7 AI assists discovery; AI does not replace the web

The search engine must continue sending users to original sources.

## 2.8 No hidden manipulation

Search controls, personalization, advertising and ranking explanations must be understandable to ordinary users.

# 9. THREE CORE SEARCH MODES

## Intelligent

Normal hybrid search.

Uses:

* lexical
* semantic
* entity
* freshness
* quality
* diversity

## Exact

Strict query interpretation.

For:

```text
"ISO 20022 pain.001"
```

prioritize the actual phrase and query tokens.

## Hybrid

Exact matches first, semantic expansion second.

This should be the default advanced mode.

# 12. RESULT DIVERSITY ENGINE

Prevent one site or one content cluster from dominating.

Default:

> Maximum 2 prominent results from the same domain when meaningful alternatives exist.

Diversity should consider:

* domain
* publisher
* content cluster
* source type
* geographic origin
* viewpoint/category differences where applicable

Do not use diversity to artificially suppress highly relevant results when no legitimate alternatives exist.

---

# 13. SEARCH QUALITY ENGINE

For each page evaluate:

### Relevance

Does the document actually answer the query?

### Originality

Is it original or copied?

### Information density

Does the page contain useful information?

### Source quality

Is the source clearly identifiable?

### Evidence quality

Does it support its claims?

### Freshness

Is the information current enough for the query?

### Expertise signals

Does the content demonstrate meaningful subject-matter knowledge?

### Spam signals

Does it exhibit manipulative search behavior?

### Duplicate signals

Is it substantially redundant?

If the system cannot establish a reliable answer:

Say:

> "I found relevant sources, but the evidence is insufficient to provide a reliable conclusion."

> "Sources disagree."

# 69. IMPLEMENTATION INSTRUCTION FOR THE AI DEVELOPER

>

# 71. FINAL PRODUCT DEFINITION

The finished platform should be understood as five systems working together:

```text
             ┌─────────────────────┐
             │   WEB SEARCH ENGINE │
             └──────────┬──────────┘
                        │
        ┌───────────────┼────────────────┐
        ▼               ▼                ▼
   Web Index       Knowledge Graph    Verticals
        │               │                │
        └───────────────┼────────────────┘
                        ▼
                SEARCH INTELLIGENCE
                        │
              ┌─────────┴─────────┐
              ▼                   ▼
        AI SEARCH             DEEP RESEARCH
              │                   │
              └─────────┬─────────┘
                        ▼
                    USER CONTROL
```

The target product is therefore:

> **An independent web search engine with its own crawling and indexing infrastructure, high-quality ranking, source transparency, user-controlled search modes, semantic retrieval, knowledge graph, specialized search verticals, privacy controls, and evidence-grounded AI research.**

The key differentiation is not simply "better AI."

It is:

> **Better retrieval + better ranking + better transparency + better user control + responsible AI.**

The first meaningful release should allow a user to:

1. Enter a query.

3. switch between Balanced, Exact and Latest.
4. restrict results to official/academic/community/news sources.
5. control freshness.
6. control domain diversity.
7. disable AI.
8. inspect why a result appeared.
9. inspect source metadata.
10. see duplicate/topic clustering.
11. receive an evidence-grounded AI summary.
12. open the original sources.
13. disable personalization.
14. use a privacy-oriented search mode.
